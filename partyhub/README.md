# PartyHub — MVP

PartyHub — адаптивная игровая платформа на Next.js, React, TypeScript и Supabase. В проекте есть главная страница, соло-викторина на 100 вопросов, гостевые комнаты, лобби с обновлением списка участников в реальном времени и сетевые раунды с серверной проверкой ответов, таймером, очками, жизнями, стриками и итоговой таблицей.

> Соло-викторина работает без аккаунта и без Supabase. Для сетевой игры необходимы Supabase, включённые Anonymous Sign-Ins и SQL-миграция. Серверная логика хранит правильные ответы в закрытой таблице и раскрывает их только в фазе результата вопроса.

## 1. Что нужно установить

- Node.js 20 или новее
- npm
- (необязательно для соло-режима) бесплатный проект Supabase

## 2. Запуск локально

В терминале в папке проекта:

```bash
npm install
npm run dev
```

Открой адрес, который покажет Next.js (обычно `http://localhost:3000`). Соло-викторина работает без дополнительных настроек.

## 3. Подключение Supabase для комнат

1. Создай проект в [Supabase](https://supabase.com/).
2. В Supabase открой **Authentication → Sign In / Providers** и включи **Anonymous Sign-Ins**.
3. Открой **SQL Editor** и выполни весь файл `supabase/migrations/0001_partyhub.sql`.
4. В **Project Settings → API** найди Project URL и publishable/anon key.
5. Скопируй `.env.example` в `.env.local` и заполни значения:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```

6. Перезапусти `npm run dev` после изменения `.env.local`.

Никогда не помещай `service_role` key в переменную `NEXT_PUBLIC_*` и не отправляй его в чат. Для текущего лобби используется только publishable/anon key, а изменения выполняются защищёнными SQL-функциями.

## 4. Проверка

- На главной нажми «Играть в викторину», выбери темы и количество вопросов.
- Выбери один из четырёх ответов. После ответа показываются правильный вариант и объяснение.
- Проверь бонус скорости, серии правильных ответов, потерю жизней и итоговый экран.
- Для сетевой игры подключи Supabase, выполни миграцию, включи anonymous sign-ins и открой проект в двух разных браузерах/устройствах для проверки кода комнаты, списка игроков и раунда.

## 5. Структура

```text
app/
  globals.css       — адаптивный тёмный UI
  layout.tsx        — корневой layout и метаданные
  page.tsx          — главная, настройки, соло-игра, результат и форма комнаты
lib/
  questions.ts      — локальная база вопросов и категории
  supabase.ts       — клиент Supabase
supabase/
  migrations/
    0001_partyhub.sql — комнаты, участники, RLS и RPC
.env.example
```

## Технические ограничения текущего MVP

- База содержит 100 уникальных вопросов — по 20 на каждую тему. Размеры раунда 10, 20, 30, 50, 75 и 100 доступны только если выбранные темы содержат достаточно вопросов. Повторы не подставляются.
- Сетевой режим использует защищённые RPC-функции Supabase для создания/входа в комнату, старта раунда, отправки ответов и получения состояния. Ответы обрабатываются сервером, повторный ответ блокируется уникальным ограничением, а таймер и фаза раскрытия управляются серверным временем. Клиент опрашивает состояние раз в секунду и получает обновления таблицы.
- До публикации необходимо запустить production build и проверить RLS/RPC в отдельном тестовом Supabase-проекте.

## Обновление 0.2: комнаты, жалобы и админка

1. Запусти новую миграцию `supabase/migrations/0002_partyhub_features.sql` в Supabase SQL Editor после `0001_partyhub.sql`.
2. Для админки создай пользователя с email и паролем в Supabase → Authentication → Users (Add user). Скопируй его UUID и выполни в SQL Editor:

```sql
insert into public.admin_users(user_id)
values ('UUID_ПОЛЬЗОВАТЕЛЯ_АДМИНА')
on conflict (user_id) do nothing;
```

3. После миграции задеплой обновлённый проект на Vercel. Админ-панель находится по адресу `/admin`.
4. Код комнаты теперь состоит из шести цифр. Миграция переводит существующие буквенно-цифровые коды на цифровые, поэтому для активных старых комнат потребуется разослать новый код.
5. Вопрос из жалоб отключается (`active=false`), чтобы не попадать в новые раунды; запись сохраняется для целостности истории ответов.

**Важно о базе вопросов:** эти изменения добавляют инфраструктуру для новых категорий, но не создают автоматически 100 качественных вопросов на каждую из 10 тем. До расширения банка база содержит прежние 100 вопросов; в новых категориях пока нет наполнения. Не выбирай новые темы в игре до загрузки вопросов для них.


## Обновление базы вопросов и настройка «Повторы»

Для обновления существующего Supabase-проекта выполни в SQL Editor по очереди:

1. `supabase/migrations/0003_question_bank_and_repeats.sql` — добавляет 100 вопросов в каждую из 10 тем (IDs 101–1100; исходные IDs 1–100 не перезаписываются).
2. `supabase/migrations/0004_repeat_setting.sql` — добавляет настройку «Повторы» и историю вопросов комнаты.

После этого загрузи обновлённые файлы в GitHub и дождись деплоя Vercel. Настройка «Повторы» находится в лобби у ведущего. Если она включена, вопросы из прошлых матчей той же комнаты исключаются при старте следующего матча; если доступных вопросов не хватает, сервер сообщит об этом и предложит выключить повторы или изменить темы/количество.


## Настройка количества жизней (обновление 0005)

В Supabase SQL Editor выполни `supabase/migrations/0005_lives_setting.sql`. В лобби ведущий может выбрать 1, 2, 3 жизни или «Безлимит». В безлимитном режиме неправильные ответы и пропуски не отнимают жизни и игроки не выбывают; ошибки по-прежнему сбрасывают серию правильных ответов. После применения миграции опубликуй обновление на Vercel.
