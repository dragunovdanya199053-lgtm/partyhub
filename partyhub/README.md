# PartyHub — MVP

PartyHub — адаптивная игровая платформа на Next.js, React, TypeScript и Supabase. В проекте есть главная страница, соло-викторина на 100 вопросов, гостевые комнаты, лобби с обновлением списка участников в реальном времени и сетевые раунды с серверной проверкой ответов, таймером, очками, жизнями, стриками и итоговой таблицей.

> Соло-викторина доступна без аккаунта. Регистрация по никнейму и паролю позволяет сохранять незавершённый прогресс соло-викторины в Supabase. Для сетевых комнат также нужны включённые Anonymous Sign-Ins. Правильные ответы сетевой игры остаются на сервере и раскрываются только в фазе результата вопроса.

## 1. Что нужно установить

- Node.js 20 или новее
- npm
- (необязательно для соло-режима) бесплатный проект Supabase

## 2. Запуск локально

В терминале в папке проекта:

```bash
npm install
npm run dev
```

Открой адрес, который покажет Next.js (обычно `http://localhost:3000`). Соло-викторина работает без дополнительных настроек.

## 3. Подключение Supabase для комнат

1. Создай проект в [Supabase](https://supabase.com/).
2. В Supabase открой **Authentication → Sign In / Providers** и включи **Anonymous Sign-Ins**.
3. Открой **SQL Editor** и выполни миграции `0001`–`0008` по порядку (см. раздел «Завоеватели и аккаунты» ниже).
4. В **Authentication → Providers → Email** отключи **Confirm email**, чтобы регистрация по никнейму не требовала подтверждения адреса. Приложение использует синтетический внутренний адрес на домене `users.partyhub.invalid` для Supabase Auth; он не предназначен для получения писем.
5. В **Project Settings → API** найди Project URL и publishable/anon key.
6. Скопируй `.env.example` в `.env.local` и заполни значения:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```

7. Перезапусти `npm run dev` после изменения `.env.local`.

Никогда не помещай `service_role` key в переменную `NEXT_PUBLIC_*` и не отправляй его в чат. Для текущего лобби используется только publishable/anon key, а изменения выполняются защищёнными SQL-функциями.

## 4. Проверка

- На главной нажми «Играть в викторину», выбери темы и количество вопросов.
- Выбери один из четырёх ответов. После ответа показываются правильный вариант и объяснение.
- Проверь бонус скорости, серии правильных ответов, потерю жизней и итоговый экран.
- Для сетевой игры подключи Supabase, выполни миграцию, включи anonymous sign-ins и открой проект в двух разных браузерах/устройствах для проверки кода комнаты, списка игроков и раунда.

## 5. Структура

```text
app/
  globals.css       — адаптивный тёмный UI
  layout.tsx        — корневой layout и метаданные
  page.tsx          — главная, настройки, соло-игра, результат и форма комнаты
lib/
  questions.ts      — локальная база вопросов и категории
  supabase.ts       — клиент Supabase
supabase/
  migrations/
    0001_partyhub.sql — комнаты, участники, RLS и RPC
.env.example
```

## Технические ограничения текущего MVP

- База содержит 100 уникальных вопросов — по 20 на каждую тему. Размеры раунда 10, 20, 30, 50, 75 и 100 доступны только если выбранные темы содержат достаточно вопросов. Повторы не подставляются.
- Сетевой режим использует защищённые RPC-функции Supabase для создания/входа в комнату, старта раунда, отправки ответов и получения состояния. Ответы обрабатываются сервером, повторный ответ блокируется уникальным ограничением, а таймер и фаза раскрытия управляются серверным временем. Клиент опрашивает состояние раз в секунду и получает обновления таблицы.
- До публикации необходимо запустить production build и проверить RLS/RPC в отдельном тестовом Supabase-проекте.

## Обновление 0.2: комнаты, жалобы и админка

1. Запусти новую миграцию `supabase/migrations/0002_partyhub_features.sql` в Supabase SQL Editor после `0001_partyhub.sql`.
2. Для админки создай пользователя с email и паролем в Supabase → Authentication → Users (Add user). Скопируй его UUID и выполни в SQL Editor:

```sql
insert into public.admin_users(user_id)
values ('UUID_ПОЛЬЗОВАТЕЛЯ_АДМИНА')
on conflict (user_id) do nothing;
```

3. После миграции задеплой обновлённый проект на Vercel. Админ-панель находится по адресу `/admin`.
4. Код комнаты теперь состоит из шести цифр. Миграция переводит существующие буквенно-цифровые коды на цифровые, поэтому для активных старых комнат потребуется разослать новый код.
5. Вопрос из жалоб отключается (`active=false`), чтобы не попадать в новые раунды; запись сохраняется для целостности истории ответов.

**Важно о базе вопросов:** эти изменения добавляют инфраструктуру для новых категорий, но не создают автоматически 100 качественных вопросов на каждую из 10 тем. До расширения банка база содержит прежние 100 вопросов; в новых категориях пока нет наполнения. Не выбирай новые темы в игре до загрузки вопросов для них.


## Обновление базы вопросов и настройка «Повторы»

Для обновления существующего Supabase-проекта выполни в SQL Editor по очереди:

1. `supabase/migrations/0003_question_bank_and_repeats.sql` — добавляет 100 вопросов в каждую из 10 тем (IDs 101–1100; исходные IDs 1–100 не перезаписываются).
2. `supabase/migrations/0004_repeat_setting.sql` — добавляет настройку «Повторы» и историю вопросов комнаты.

После этого загрузи обновлённые файлы в GitHub и дождись деплоя Vercel. Настройка «Повторы» находится в лобби у ведущего. Если она включена, вопросы из прошлых матчей той же комнаты исключаются при старте следующего матча; если доступных вопросов не хватает, сервер сообщит об этом и предложит выключить повторы или изменить темы/количество.


## Настройка количества жизней (обновление 0005)

В Supabase SQL Editor выполни `supabase/migrations/0005_lives_setting.sql`. В лобби ведущий может выбрать 1, 2, 3 жизни или «Безлимит». В безлимитном режиме неправильные ответы и пропуски не отнимают жизни и игроки не выбывают; ошибки по-прежнему сбрасывают серию правильных ответов. После применения миграции опубликуй обновление на Vercel.

## Игра «Завоеватели» (новый режим)

В проект добавлен отдельный маршрут `/conquerors`. Классическая викторина остаётся в `app/page.tsx` и продолжает использовать прежние RPC. Новый режим использует отдельные таблицы и функции Supabase из миграции `supabase/migrations/0006_conquest_game.sql`.

### Правила MVP

- 2–6 игроков, фиксированная карта из 30 территорий с заранее заданными связями.
- В начале у каждого игрока своя столица.
- Ходящий игрок выбирает соседнюю нейтральную территорию для захвата или территорию соперника для атаки.
- Захват нейтральной территории требует минимум 2 правильных ответа из 3.
- В атаке оба участника отвечают на три общих вопроса. За правильный ответ начисляется 1000 очков и бонус скорости до 500; неправильный ответ даёт 0. При равенстве побеждает защитник.
- Потеря столицы означает выбывание; владения выбывшего игрока становятся нейтральными.
- После потери связи остальные клиенты отмечают игрока отключённым. У него есть 2 минуты на возврат; затем фиксируется сдача, владения становятся нейтральными, ход пропускается. Переподключение доступно из того же гостевого сеанса браузера.

### Запуск локально

1. Установи Node.js 20 или новее.
2. Скопируй `.env.example` в `.env.local` и заполни URL и anon/publishable key проекта Supabase.
3. В Supabase SQL Editor примени миграции в порядке `0001` → `0002` → `0003` → `0004` → `0005` → `0006` → `0007` → `0008`. Если проект уже работает на `0007`, применяй только `0008_conquerors_fixes.sql`.
4. В Supabase Authentication включи **Anonymous sign-ins** и отключи **Confirm email** в Email provider.
5. Запусти `npm install`, затем `npm run dev`.
6. Открой `http://localhost:3000/conquerors` или нажми «Завоеватели» на главной странице.

### Публикация на GitHub и Vercel

- Загрузи содержимое папки проекта в репозиторий GitHub.
- В настройках проекта Vercel добавь `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` в Environment Variables.
- Убедись, что миграции `0006_conquest_game.sql` и `0007_username_auth_and_progress.sql` применены в том же Supabase-проекте, который указан в Vercel.
- После изменения SQL применяй миграции вручную в Supabase SQL Editor; деплой Next.js сам по себе SQL не запускает.

### Важное ограничение первой версии

Это первый интегрированный MVP режима. Он использует гостевую авторизацию Supabase и опрос состояния с клиентов. Перед публичным запуском рекомендуется провести тесты нескольких одновременных партий, сценариев потери соединения и повторного входа; для гарантированного продакшен-таймера сдачи нужен отдельный серверный планировщик/cron, поскольку срок обрабатывается при следующем вызове состояния игры.


## Аккаунты по никнейму и сохранение прогресса

- Регистрация и вход выполняются по никнейму (3–20 букв латиницы/кириллицы, цифр, `_` или `-`) и паролю от 8 символов. Подтверждение email не используется.
- Supabase Auth требует идентификатор в формате email для password sign-in, поэтому приложение кодирует никнейм в детерминированный синтетический адрес на домене `users.partyhub.invalid`. Реальный адрес пользователя не запрашивается, письма на этот адрес не доставляются.
- В Supabase отключи `Authentication → Providers → Email → Confirm email`. Если подтверждение оставить включённым, регистрация не сможет сразу войти в аккаунт.
- Применяй `supabase/migrations/0007_username_auth_and_progress.sql` после `0001`–`0006`. Миграция добавляет профили с уникальными никнеймами и таблицу `solo_game_progress` с RLS, ограничивающей данные владельцем аккаунта.
- Незавершённая соло-викторина автоматически сохраняется у вошедшего пользователя; после входа на главной появляется кнопка «Продолжить игру». Если пользователь уже играет как гость, регистрация повышает эту же сессию до постоянного аккаунта, чтобы не потерять участие в текущей комнате.
- Восстановление забытого пароля через email не предусмотрено, так как пользователь не указывает почту. Если потерять пароль, стандартный сброс пароля будет невозможен.


## Исправления «Завоевателей» (миграция 0008)

После применения миграций `0001`–`0007` выполни `supabase/migrations/0008_conquerors_fixes.sql` в Supabase SQL Editor. Она: 

- автоматически использует никнейм профиля для вошедшего пользователя;
- исключает повторное использование вопросов в рамках одной партии «Завоевателей»;
- добавляет кнопку «Новая игра», которая возвращает всех участников в лобби;
- позволяет ведущему запускать повторную партию в той же комнате без удаления игроков.

## «Завоеватели» — карта 0.3.1

Для существующей базы примените миграции по порядку до `0009_conquerors_map_031.sql` включительно. Миграция 0009 добавляет каноническую карту из 30 территорий, стартовые столицы T01/T06/T11/T16/T21/T26, экономику и эффекты особых территорий. Классическая викторина и банк вопросов не сбрасываются.

- Каждый свой ход приносит `+1` золото за каждую принадлежащую территорию; Золотые копи добавляют ещё `+10`.
- Первое завоевание нейтральных Пепельных окраин, Забытых башен, Каменной границы и Долины стражей приносит соответственно `+20/+40/+60/+100` золота. Награда не фармится повторными захватами.
- Лес и горы дают защиту `+100`; Древний лес и Королевский мост — `+250`; Железная Стража — `+500`. Бонус территории не суммируется с другими базовыми бонусами; вложенная защита добавляется отдельно.
- Вложение: `1` золото даёт `+10` защиты, максимум `+500` на территорию. Вложенная защита сбрасывается при смене владельца.
- Владение Свободным портом позволяет начинать морские атаки на любую прибрежную территорию, включая вражеские столицы; стандартные правила боя и защиты продолжают действовать.
- Академия мудрецов позволяет убрать один неверный вариант после трёх завершённых боёв игрока, пока он владеет Академией.
- Захват Цитадели даёт `+500` к результату следующих пяти PvP-сражений и запускает таймер в 15 полных раундов. По истечении таймера Цитадель возвращается нейтральному королевству.

Новая миграция не меняет карту уже идущих партий. Для чистой проверки создайте новую комнату после применения миграций. SQL следует применять в Supabase SQL Editor по порядку; после применения проверьте создание комнаты и старт матча на тестовых аккаунтах.
